## Root cause and local proof

- GitHub deploy run `29139277754` proves the DB Machine reached `stopped` immediately, yet the old deploy script accepted it as good. Auth and REST then returned 503 while liveness stayed green.
- The exact pinned image is `supabase/postgres:17.6.1.136@sha256:f371...c00`.
- Local Docker reproduction against that exact image proved:
  1. Mounting a volume containing `lost+found` at `/var/lib/postgresql/data` makes `initdb` exit 1 because the data directory is not empty.
  2. Setting only `PGDATA=/var/lib/postgresql/data/pgdata` is not a valid fix. Initialization uses the subdirectory, but the image starts `postgres -D /etc/postgresql`, whose config pins `data_directory=/var/lib/postgresql/data`; startup still fails.
  3. Mounting the volume at `/var/lib/postgresql` keeps the effective data directory at the durable child `/var/lib/postgresql/data`; the exact application DB image becomes ready and persisted a probe across two restarts.
- The exact-image test found and fixed a second first-boot crash: `docker/db/01-roles.sql` unconditionally altered the extension-dependent `supabase_functions_admin` role, which the pinned image may omit. Core connection roles remain required; only that optional role is now conditional.
- A fail-closed wrapper now exits 78 if an old root-level PostgreSQL cluster or unexpected volume entry exists. This prevents the mount change from silently hiding an old cluster and initializing an empty one under `data/`.

## Watch out

- Changing a volume mount point can hide an existing cluster. The entrypoint guard prevents silent startup, but it does not replace a preserved-clone inspection.
- Replacing an inherited Docker entrypoint resets inherited command behavior unless CMD is restated. The DB Dockerfile now explicitly keeps `postgres -D /etc/postgresql`.
- A stopped DB makes sibling `.internal` resolution fail. Fix and prove the DB before chasing DNS.
- Never scale `aria-mantu-db` above one Machine in this topology; a second Machine is not a replica.
- `/api/health` is liveness only. Production acceptance requires `/api/ready`, migration/digest identity, persistence, recovery, and E2E proof.
