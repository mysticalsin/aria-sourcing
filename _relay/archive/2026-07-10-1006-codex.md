  - `DatabricksSettings` exists on `SystemSettings`.
  - `"Databricks"` exists in `API_KEY_PROVIDERS`.

  - Settings -> Integrations now has an admin-only Databricks intake panel for host, warehouse id, auth mode, client id, stored key id, and needs SQL.
- Stored Databricks secrets resolve by exact `api_keys.id` plus workspace id and provider, not newest provider row:
  - `resolveStoredDatabricksSecret(session, apiKeyId)` in `src/lib/sourcing/tavily.ts`.
- The Databricks Statement Execution client is Supabase-free:
  - `src/lib/integrations/databricks.ts`.
  - PAT passes through as bearer token.
  - OAuth M2M fetches `{host}/oidc/v1/token` with HTTP Basic and caches the token for up to 55 minutes by `host|clientId`.
  - Statement body uses `parameters: [{ name: "since", value, type: "TIMESTAMP" }]`, `INLINE`, `JSON_ARRAY`, `row_limit: 500`.
  - `PENDING`/`RUNNING` polls `GET /api/2.0/sql/statements/{id}` with a 5-poll cap.
  - `manifest.schema.columns` and `result.data_array` map to row objects; malformed row arrays and nulls are skipped.
- Route exists:
  - `src/app/api/integrations/databricks/needs/route.ts`.
  - Order: `prodFailClosed` -> live workspace/session auth -> RBAC `source` -> rate limit -> body validation -> workspace settings -> `assertPublicUrl(host)` -> key-id secret resolution -> Databricks execution.
  - Route header documents private-link/internal Databricks workspaces as out of scope for this wave.
  - Success response is `{ ok: true, proposals: ParsedIntake[] }`.
  - The server never calls `createCampaignFromAnalysis` and has no campaign/store write path.

## Decisions made (don't relitigate)
- Databricks API key config is split: non-secret connection fields in `settings.databricks`, secret in encrypted `api_keys` by exact id.
- Private-link/internal Databricks workspaces are out of scope for W4 because the route must use `assertPublicUrl` before Databricks fetches.
- The route rejects a `needsQuery` that does not contain `:since`.
- Server output remains proposal-only; human confirmation in the intake UI is the only campaign-creation path.
- `sinceColumn` is stored for config completeness but not interpolated into SQL. The SQL template must own column use and `:since` binding.
